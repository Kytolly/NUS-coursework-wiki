# 话务建模与话务强度

> 本页属于：CEG5104 / Week 02
> 前置知识：[[CEG5104-讲义与笔记索引]]
> 预计阅读时间：6 分钟

**单个用户的呼叫过程**是一个随机过程（stochastic process），可用时间轴上的 BUSY（1）/IDLE（0）表示。要刻画它，需要三样东西：BUSY 时段的统计分布、IDLE 时段的统计分布，以及过程的“记忆”（过去的占用是否影响未来开始呼叫的概率）。（来源：2_capacity_analysis.pdf 第 15 页。）

**话务使用参数**有两个：呼叫率（call intensity）$\lambda$ = 每小时呼叫数；呼叫保持时间（call holding time）$h$ = 平均一次通话占用时长。（来源：2_capacity_analysis.pdf 第 16 页。）

**话务强度**（traffic intensity）记为 $A = \lambda h$，单位是 **Erlang（erl）**，无量纲，同时等于“用户处于忙态的概率”。例：1 小时 1 次呼叫、每次平均 120 秒，则 $A = 120/3600 = 1/30\text{ Erl}$，等价于用户 60 分钟里忙 2 分钟（用户忙的概率 $= 2/60 = 1/30$）。（来源：2_capacity_analysis.pdf 第 17–19 页。）

**多用户**：若 $M$ 个用户各自强度为 $A_i$，总话务 $A = \sum A_i = M A_i$；活跃呼叫数服从**二项分布** $P[k] = \binom{M}{k} A_i^k (1 - A_i)^{M-k}$，均值 $= M A_i = A$。例：5 用户每人 3 次/时、每次 4 分钟 $\to A = 5 \times 3 \times (4/60) = 1\text{ Erl}$，实际活跃数在 0–5 之间波动，各活跃数的概率如下表（来源：2_capacity_analysis.pdf 第 20–21 页）：

| 活跃用户数 $k$ | 概率 $P[k]$ |
| --- | --- |
| 0 | 0.327680 |
| 1 | 0.409600 |
| 2 | 0.204800 |
| 3 | 0.051200 |
| 4 | 0.006400 |
| 5 | 0.000320 |

再例：30 用户每人 1 次/时、每次 4 分钟 $\to A = 2\text{ Erl}$；平均约 2 路同时活跃，常见 4–5 路，超过 8 路概率约 0.01%，超过 11 路约百万分之一。（来源：2_capacity_analysis.pdf 第 22 页。）这引出**话务工程**问题：该给这些用户预留多少信道？

**无限用户 → 泊松**：当 $M \to \infty$ 且总强度 $A$ 固定（每用户 $A_i = A/M$），二项分布收敛到**泊松分布**：

$$
P[k\text{ 路活跃呼叫}] = \frac{A^k e^{-A}}{k!}
$$

$A$ 相对 $M$ 很小时与二项分布吻合良好（如 $M=30$、$A=2$ 时几乎重合），且比二项分布更简单、无繁琐组合数。（来源：2_capacity_analysis.pdf 第 23–24 页。）

**信道有限 → 呼损**：当信道数 $C$ 小于用户数 $M$ 时，部分呼叫会被阻塞（blocked）。呼损概率为：

$$
P[\text{block}] = \frac{\text{承载呼叫数}}{\text{提供呼叫数}} = P[\text{恰好 } C \text{ 个被接受}]
$$

于是要从“提供呼叫数”的表达式出发，求“被接受呼叫数”的表达式。（来源：2_capacity_analysis.pdf 第 25 页。）另外注意：$A$ 以 Erlang 为单位，但实为**无量纲**——它既等于单用户处于忙态的概率，也等于多用户场景下平均同时活跃的呼叫数。因此 $A$ 可同时理解为“强度”与“平均并发呼叫数”，这解释了为什么 $A=1$ 的 5 用户例中平均恰好 1 路，$A=2$ 的 30 用户例中平均 2 路。泊松分布无记忆、参数单一（只需 $A$），因此是后续呼损分析（Erlang-B/C）的公共出发点，这也是先讲二项分布再讲泊松收敛的原因。

```mermaid
flowchart LR
  A[单用户 BUSY/IDLE 随机过程] --> B[呼叫率 λ + 保持时间 h]
  B --> C[A = λ·h Erlang]

  D -->|有限 M| E["二项分布 P[k]=C(M,k)A_i^k(1-A_i)^(M-k)"]
  D -->|M→∞ 且 A 固定| F["泊松分布 P[k]=A^k e^-A/k!"]
  E --> G[信道数 C < 用户数 M => 呼损]

  G --> H[待求: P[block] 由“被接受呼叫数”给出]
```
